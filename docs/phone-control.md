# 手机热点遥控、视频与二维码

更新：2026-11-20。按用户最新要求，采用手动上锁/解锁、350/750µs升降目标（恢复可响应的低位），并增加麦轮横移。

1. 手机连接 `Pi5-Control`，热点密码查看本机网络设置。如提示无互联网，选择保持连接。
2. 浏览器打开 `http://10.42.50.1:8080/`，输入当前网页口令。口令位于本机 `~/.config/dase7503/remote-password`，与热点密码独立，不纳入仓库。更新服务后刷新并重新登录。
3. 服务启动时锁定，点击“解锁驾驶”后可操作，按钮变为“上锁驾驶”。动作结束、松手、急停、页面隐藏或失联只停车，保留手动解锁选择；只有点击“上锁驾驶”才锁定。服务重启从锁定状态开始。前进、后退、左平移、右平移及独立左转/右转均按住持续、松开停车。
4. 停车后点“降下”将目标设为当前偏高的下降位置 350µs；“升起”为 750µs。切换后约 2 秒内底盘禁止运动。开机、登录或更新服务时不自动将升降台归位。
5. “紧急停车”停止底盘，离开页面或手机锁屏也会停车；已手动解锁时，下一次主动按键即可继续。250ms命令静默归零和板端失联保护保留，手机停止发命令后不会自动继续走。松手/急停会淘汰此前手势的迟到指令，不弹锁定错误。急停不撤销已经发送的舵机位置保持。

## 视频与扫码

- 登录后自动显示摄像头 MJPEG 连续流，分辨率 960×540，实测约 9–10fps；默认上限 12fps。相机连续自动对焦。
- MJPEG通过现有HTTP服务与登录Cookie传输，手机无需安装客户端或互联网。网页显式读取视频流，检测正常结束、错误和2.5秒无新帧并自动重连；重连时保留上一帧，标示“重连中”，不再依赖浏览器图片错误事件。短暂状态请求失败不会拆掉视频连接；隐藏页面时断开视频并停车。
- 在树莓派独立视觉进程本地扫码，目标 5Hz。连续三帧确认后，画面标框，“最近识别”显示内容及时间，并自动保存 PNG 截图与 JSONL 记录。静止对准二维码通常约 0.4–0.6 秒可确认，实际取决于清晰度和负载。
- 支持 START、END、课程 RACKA/B/C/D 码和普通 UTF-8 文本/网址。网址只作为文本显示，不自动访问；二维码不会触发任何行驶或升降。
- 同样内容在当前进程及重启后均只保存一次。历史记录可在“二维码留证”查看，点击卡片打开截图；也可用“保存当前截图”手动保存。
- 图片与记录保存在 `~/dase7503_evidence/`。通用文本只通过哈希构成文件名，原文保存在记录中。

选择 MJPEG 是为了直接复用本机 JPEG 编码与手机浏览器显示能力，无需额外的信令、视频客户端或公网服务。相机先压缩图像后经 ROS 传给视觉进程，视觉进程输出带框 JPEG；网页控制进程只接收压缩字节，不执行扫码或视频编码。HTTP 视频只保留最新帧，限制至多三个视频连接，并为控制请求保留线程。

## 运行方式

统一 `dase7503.target` 已启用，linger 开启，可在未登录桌面时启动五项常驻服务：

- `dase7503-agent`：ESP32 串口通信。启动前整理 CP2102 控制线，可能复位 ESP32；不发送运动或升降指令。
- `dase7503-camera`：IMX708 相机，960×540 BGR，采集上限 20fps，输出 JPEG。
- `dase7503-vision`：扫码、标框、截图与预览 JPEG 编码。与驾驶控制分属进程。
- `dase7503-health`：监测相机/扫码/控制板真实数据与网页控制循环，卡住时重启对应服务；自身30秒systemd看门狗。
- `dase7503-remote`：等待 `wlan0` 获得 `10.42.50.1/24` 后启动网页，只监听 `10.42.50.1:8080`。

现有 NetworkManager `Pi5-Control` 配置负责热点自启。没有修改 USB 网卡、默认路由、策略路由、代理配置或 DNS。重启网页/视觉服务无需重启串口通信服务。

检查状态：

```bash
systemctl --user status dase7503.target dase7503-agent dase7503-camera dase7503-vision dase7503-remote dase7503-health
journalctl --user -u dase7503-vision -u dase7503-remote -n 30
```

停止服务：

```bash
systemctl --user stop dase7503.target
```

重新安装已授权配置：

```bash
source tools/environment.bash
python3 tools/install_phone_remote.py --services-only --enable
systemctl --user restart dase7503.target
```

部署配置为 `~/.config/dase7503/phone-profile.yaml`，主硬件配置保持原样。用户确认了原有驾驶和 400/540µs 升降；配置保留此反馈，350/750µs 是当前手动目标，未把它自动标记为机械行程验收通过。本次软件更新不主动驱动底盘或舵机。

## 横移映射与手动状态

旧代码只混合前进和旋转，并明确拒绝 lateral，所以原按钮只能左右旋转。现在采用标准X型麦轮混控，按已确认轮位M1右前/M2左前/M3右后/M4左后，以及物理前进PWM符号[-1,+1,-1,+1]输出。左平移物理轮向为[前,后,后,前]，原始PWM为[-600,-600,+600,+600]；右平移完全相反。组合指令统一缩放，PWM不超过600。运动学参考：[WPILib mecanum drive](https://docs.wpilib.org/en/stable/docs/software/kinematics-and-odometry/mecanum-drive-kinematics.html)。

`manual_lateral_authorized=true`记录用户请求，`lateral_response_verified=false`与`roller_orientation_verified=false`保留：软件与模拟链路通过不能替代实车左右方向确认。此次不自动发横移或300µs实车命令。

手动解锁选择与板端实际使能分开。250ms无指令、反馈中断或板端复位仍会使输出归零、撤销实际使能、丢弃旧运动和未发送的升降目标；连接恢复本身不恢复运动。只有新的主动操作才能在手动解锁状态下重新完成板端零输出握手。每个手势编号阻止迟到的指令撤销停车/上锁；手动模式拒绝缺少编号的旧页面请求。
